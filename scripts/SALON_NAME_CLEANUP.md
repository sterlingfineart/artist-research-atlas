# Salon artist-name cleanup — build note (phase 1, November 2026)

## What this is

An automated, conservative cleanup of garbled artist names in the
Salon Time Machine (`#/salon`). It corrects artist **surnames, given
names, and teachers** where the OCR of the printed livrets misread
them. It does **not** touch titles, mediums, catalogue numbers,
birthplaces, or notes — those are a later phase.

The correction is applied at display time, in memory, from a mapping
file. The per-year data files (`public/data/salon/*.json`) and the
master source (`~/workspace/salon-database/data/salon-all.json`) are
**unchanged** — the original printed spellings are preserved in the
data, and the corrections survive any rebuild of the per-year files.

## Files

| file | purpose |
|---|---|
| `public/data/salon/name-corrections.json` | The durable mapping the site loads: `{"given": {...}, "surname": {...}, "teacher": {...}}`, keyed by the exact garbled string, global across years. 7,775 mappings. |
| `public/app.js` | `viewSalon` fetches the mapping once (cached) and applies it to the works array in memory right after loading a year file, before search / filter / pagination. |
| `scripts/salon-name-review-list.md` | Human-readable list of the 40,232 garbled forms that were deliberately **not** corrected, with counts, examples, and why. |
| `scripts/build-salon-data.py` | Unchanged. The per-year files it generates are not regenerated by this cleanup. |

Working files (not in the repo) live in
`~/workspace/salon-database/cleanup/`: `compute_given.py`,
`compute_surname.py`, `compute_teacher.py`,
`build_corrections_file.py`, the Wikidata cache
(`wikidata/artists.json`, `wikidata/authority2.json`), and the
machine-readable review lists (`given_review.json`,
`surname_review.json`, `teacher_review.json`).

## Method

### Reference data

- **Wikidata SPARQL** (query.wikidata.org, fetched November 2026,
  ~4 minutes, cached): 126,530 people with occupations painter,
  sculptor, architect, engraver, draftsperson, or printmaker, born
  1550–1900 (plus an undated slice). From these, an authority set of
  24,075 given-name keys and 84,019 surname keys (with per-name
  person counts and original-case forms). Wikidata is used here only
  as a finding aid for *whether a string is a real name* — never as
  line-1 authority for a fact on the site.
- **Data-bootstrapped dictionary**: the most frequent clean names in
  the Salon data itself (Jean, Louis, Marie, Pierre, …) are almost
  certainly correct and form the working dictionary; rare garbled
  forms are matched to them.

### Given names (5,913 corrections, 18,254 records)

Tier A targets are clean single-token given names attested in the
data (count ≥ 5) **and** in the Wikidata given-name set with ≥ 5
distinct persons. A correction fires only when there is exactly one
Tier A candidate at edit distance 1 — or distance 2 when the garbled
part contains OCR garbage (non-letter characters). A part that is
itself a real given name is never "corrected" (the Roland / Rolland
trap). Case-only and accent-only differences are not corrections.
Honorifics (Mme. / Mlle. / M.) are a separate closed set with
confident patterns (`Mm*.` → `Mme.`, `M™e.` → `Mme.`); `M` plus
pure garbage (`M««.`, `M^^.`) is genuinely ambiguous (Mme vs Mlle)
and goes to review. Separators are preserved (space stays space,
hyphen stays hyphen); join rules rescue split names (`lé on` →
`Léon`, `je an-Baptiste` → `Jean-Baptiste`, `P I E R R E` →
`Pierre`).

### Surnames (1,847 corrections, 4,341 records)

- **"M " prefix rule** (12 forms, 736 records): a surname starting
  with `M ` (Monsieur) is corrected to the remainder when the
  remainder is attested as a surname in the data (count ≥ 3) **and**
  in the Wikidata surname set (e.g. `M ALLIER` → `ALLIER`,
  `M GAYRARD` → `GAYRARD`). A remainder attested in Wikidata but
  not in the data is too weak to trust and goes to review.
- **Clustering** (1,835 forms): a rare surname key (count ≤ 5)
  within edit distance 1 of a frequent surname key (count ≥ 30,
  ratio ≥ 5) is corrected when the candidate is unique, the target
  is a real surname (in Wikidata), and the garbled form is **not**
  itself a real surname. Distance 2 is allowed only for long keys
  (≥ 8 chars) with a unique candidate, target in Wikidata,
  ratio ≥ 20 (331 forms, 491 records). When several candidates
  qualify, the one whose artists share a given name with the
  garbled form's artists wins — the same person exhibiting under
  two spellings (e.g. `JODY` → `JOUY`, not `JOLY`, because the
  Joseph-Nicolas records match Jouy; confirmed against the 1873
  livret's rewarded-artists list, which names
  `JOUY (Joseph-Nicolas)`). If no candidate shares a given name,
  the form goes to review.
- **Guard:** a garbled form that is itself a real surname is never
  corrected (e.g. `OEL` → `NOEL`, `MARTYN` → `MARTIN`,
  `DAVY` / `DAVIES` → `DAVID` all stay in review). Fourteen further
  plausible real surnames that Wikidata's artist set does not know
  were audited by hand and moved to review on the evidence of a
  consistent multi-year run with no given-name overlap with the
  would-be target: `COLON`, `ROTER`, `LOZIER`, `RICHNER`, `BURE`,
  `PILLETTE`, `BOUCHU`, `PEAU`, `DAVE`, `PATOU`, `FOUCHET`,
  `GIRAUDON`, `BRULE`, `DUCHENNE`, `DANJOU`.
- **Never corrected:** `DESSINS` (573 records) — a section header
  parsed as a surname, not a name — and its garbles; descriptors
  (`dit …`, `l'aîné`, `le jeune`); the word fragment `ment`.

### Teachers (15 corrections, 21 records)

The surname treatment is applied to teacher values that look like
names, very conservatively: a single surname (or initial + surname,
or given name + surname), short (≤ 40 chars), no address markers,
no institution words, no parentheticals, no line-break splits, no
compound lists. Teacher values with an address, compound lists
(`MM. Gérôme et Lequien`), and hyphen-split surnames
(`M. Bogo- luboff`) go to review. Plausible real surnames
(`Goret`, `Gaudron`, `Glaude`, `Grot`, `Brevet`, `Touillon`) are
left alone. Common legit values (`son père`, `Picot`, `Ingres`,
`Gleyre`, `L. Cogniet`) are untouched.

## What was deliberately NOT fixed

- Titles, mediums, catalogue numbers, birthplaces, notes (phase 2).
- Years 1673 / 1699 / 1704 (prose fragments, not livret name
  fields).
- Any name where the correction was not high-confidence — it stays
  as printed and is listed in `scripts/salon-name-review-list.md`.
- `DESSINS` and its garbles; descriptors; unreadable honorifics
  (`M««.`, `M^^.` — Mme vs Mlle cannot be told apart).
- `E. ToilUez` (teacher of Albert Adan): `Toillez` is not in
  Wikidata and is not attested as a surname in the data, so it
  cannot be confirmed; it stays as printed.

## Rebuilding

To recompute the mapping from scratch, run in
`~/workspace/salon-database/cleanup/`:
`compute_given.py`, `compute_surname.py`, `compute_teacher.py`,
then `build_corrections_file.py`. Eyeball the top corrections and
the review lists before accepting them — in particular the
distance-2 long-key surname list and any new `cluster-d1-given`
resolutions. The Wikidata authority cache
(`wikidata/authority2.json`) can be reused; re-fetch with
`fetch_wikidata.py` + `build_authority2.py` if it goes stale.
